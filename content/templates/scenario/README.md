# Формат сценария — эталон

Эта папка — **эталонный шаблон сценария** для вики «Los Angeles by Night» (Vampire: The
Masquerade 5e, движок Quartz v4). На неё опираются сценарные скиллы (`scenario-enrich`,
`scenario-loop`), субагенты (`scenario-drafter`, `scenario-enricher`, `scenario-reviser`)
и правило `scenarios.mdc`. Здесь же — канонический **DoD сценария** (см. ниже).

## Где что лежит (и почему)


| Что                        | Путь                            | git     | Публикуется Quartz |
| -------------------------- | ------------------------------- | ------- | ------------------ |
| **Эталон/шаблон** сценария | `content/templates/scenario/`     | да  | **нет**                |
| **Реальные сценарии**      | `content/st/scenarios/<название>/` | да | **да, но unlisted**    |


- `templates` входит в `ignorePatterns` (`quartz.config.ts`), поэтому эталон **не попадает
в публикацию**, но остаётся в git и переносится при клоне репозитория. Это важно: правила
и скиллы (git-tracked) могут надёжно ссылаться на шаблон именно здесь.
- Реальные сценарии лежат в `content/st/` → они **в git** и **публикуются как «unlisted»**:
доступны по прямому URL, но скрыты из навигации, поиска, графа, `sitemap.xml` и RSS (см.
`wiki-conventions.mdc`, раздел «Видимость»). Это материалы Рассказчика — **не ссылаться** на
них из публичных заметок и **не ставить им теги**, иначе скрытие протекает. Если что-то нужно
скрыть от игроков **совсем** — держать вне сайта в `private/` (там `сценарий.md` не публикуется).

> **Не перемещать эталон в `content/` вне `templates/`** — иначе он попадёт в публикуемую
> вики. Шаблон должен оставаться внутри `content/templates/`.

## Сценарий — это папка

Реальный сценарий — это **папка** `content/st/scenarios/<название>/`, а не один файл:

```
content/st/scenarios/<название>/
├── сценарий.md        # основной файл (по эталону этой папки)
├── <раздатки>.*       # co-located материалы: карты, изображения, тексты
└── _loop/             # рабочие файлы лупа (создаёт scenario-loop)
    ├── loop_log.md     # лог проходов: фаза, проход, изменения, время
    └── <черновики>.md  # промежуточные черновики проходов
```

- Co-located раздатки кладутся рядом с `сценарий.md` и подключаются относительными путями.
- Подпапка `_loop/` — служебная: её создаёт скилл `scenario-loop` для черновиков проходов и
журнала сходимости (`loop_log.md`). Финальный сценарий живёт в `сценарий.md`, `_loop/`
можно не трогать после готовности.

## Frontmatter

Поля frontmatter эталонного `сценарий.md`:


| Поле      | Назначение                                                                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`   | Название сценария.                                                                                                                                      |
| `status`  | Стадия: `draft` / `в работе` / `готов`.                                                                                                                 |
| `created` | Дата создания (`ГГГГ-ММ-ДД`).                                                                                                                           |
| `domains` | Задействованные домены/районы (например, Голливуд, Побережье).                                                                                          |
| `npcs`    | Ключевые НПЦ сценария.                                                                                                                                  |
| `players` | (опц.) Персонажи игроков, под которых пишется сценарий.                                                                                                 |
| `draft`   | `true`, пока сценарий не готов. Фильтр Quartz `RemoveDrafts` **исключит черновик из сборки**, пока флаг стоит — удобно: незавершённый сценарий не попадёт даже на unlisted-страницу. Снимать при готовности. |


## Структура `сценарий.md`

Сценарий состоит из двух частей: **`# Справочник`** (всё, что Рассказчик держит под рукой)
и **`# Сюжет`** (сцены по порядку игры). Правила и статблоки живут в справочнике, **не
посреди сцен** — сцена только отсылает к нему.

`# Справочник` (порядок разделов гибкий):

1. `## <Фон / экосистема>` — образ, через который читается место действия (кто кем
   кормится, кто кого держит), прозой.
2. `## <Механики истории>` — опц.: сквозные механики/домашние правила этой истории.
3. `## Противники` — статблоки всех возможных противников, взятые/адаптированные из книг
   правил (`books/`), сгруппированные по типу (животные / смертные / гули / нежить).
4. `## <Место действия>` — справка по району со `[[ссылками]]`, ключевые лица, картинка
   (если файл существует), контраст дня и ночи, локальные факты этой истории.
5. `## Что произошло на самом деле` — полная картина для Рассказчика: кто, зачем и какие
   ошибки совершил до появления котерии. Игроки собирают её по кусочкам из сцен.

`# Сюжет`:

1. `## Вступление` — цель истории, варианты входа для любой котерии, зацепки списком;
   каждая зацепка должна получить развязку в сценах.
2. `## <Сцены>` по порядку игры, включая `## Перерыв` (точки передышки). Внутри сцены:
   описание прозой → реплики НПЦ блок-цитатами → улики и проверки списками → ремарки
   Рассказчика курсивом.
3. `## Эпилог` — исходы по веткам, опыт, последствия, подразделы про цену ключевых
   провалов («Если полиция найдёт трупы»).

## Тон и стиль

Как пишутся сценарии (примеры — из «Зверя», `content/st/scenarios/Зверь/`):

- **Справочник открывается образом-метафорой**, а не перечнем фактов: *«Жизнь в районе
  похожа на пищевую цепочку, в самом низу которой находятся иммигранты и американская
  беднота…»* — и дальше вся политика района читается через эту картину.
- **Контраст дня и ночи** в описании места: днём — школьные автобусы и детские площадки,
  ночью — «тихие жилые улицы погружены в мягкое свечение уличных фонарей». Смертная жизнь
  показывается тепло и подробно, чтобы ночная хищность читалась на её фоне.
- **Реплики НПЦ** — блок-цитаты с курсивной подводкой (*«Чарли о музыке:»*), живым языком
  с характером и оговорками: «Ни в жисть снова туда не пойду, а не то ж стану волчьей
  сытью».
- **Ремарки Рассказчика** — курсивом внутри сцен: тайминг, поведение противника, запасные
  ходы («Если они не догадываются, можно дать дополнительные подсказки…»).
- **Улики** — списками под условием («Если персонажи осматривают тела:»), каждая строка —
  факт плюс то, что он даёт игрокам.
- **Конкретика вместо общих слов:** марки мотоциклов, песня на повторе («Beast» от
  Rob Zombie), имена и приметы каждого статиста, цифры населения. Деталь работает лучше
  эпитета.
- **Мрачно, буднично, без пафоса**; допустима тихая ирония в деталях (лошадь Груша,
  скучающий коп с конусами), но не комедия и не отсылки «из-за стола» — тон и термины по
  `vtm-glossary.mdc`.

## Создание нового сценария

1. Скопировать папку `content/templates/scenario/` в `content/st/scenarios/<название>/`
  (и удалить из копии этот `README.md` — он про шаблон, не про конкретный сценарий).
2. Переименовать/заполнить `сценарий.md`: заменить плейсхолдеры `<…>`, удалить служебный
  info-блок и подсказки.
3. Проставить `[[ссылки]]` **только на существующие** заметки вики (проверять цель через
  ripgrep/glob перед вставкой). Несуществующих сущностей — либо создать через `note-create`,
   либо держать локальными статистами без ссылки.
4. По мере готовности менять `status` и снимать `draft: true`.

## Связь со скиллами и субагентами

- **`scenario-loop`** — оркестратор итеративного написания сценария по промпту
(plan-loop-стиль): фазы анализ → черновик → обогащение → ревизия, лог проходов в
`_loop/loop_log.md`, сходимость по DoD и отдельному style-check Labynight. Создаёт папку
сценария из этого эталона и подпапку `_loop`.
- **`scenario-enrich`** — обогащение существующего сценария/фрагмента материалами из вики и
книг (цитаты разделов); переиспользует `lore-search`.
- Субагенты по фазам: `scenario-drafter` (черновик), `scenario-enricher` (обогащение лором),
`scenario-reviser` (ревизия и проверка DoD).

> Точные триггеры и алгоритмы — в самих `SKILL.md` соответствующих скиллов; здесь только
> ориентир. Запуск, как правило: «напиши сценарий про …» / «scenario-loop …».

## DoD сценария (Definition of Done)

Это **канон** — остальные места (правило `scenarios.mdc`, субагент `scenario-reviser`)
ссылаются на него, не переписывают. Сценарий **готов**, когда:

- Есть **справочник в начале**: фон/экосистема, статблоки противников (по книгам правил
из `books/`), справка по месту действия и раздел «Что произошло на самом деле», дающий
Рассказчику цельную картину истории.
- Прописаны **все сцены сюжета** (каждая — место, участники, что узнают игроки, проверки
«Атрибут + Навык (Сложность)», исход), без оборванных нитей; **каждая зацепка вступления
получает развязку**.
- **Ключевые НПЦ и локации** проставлены `[[ссылками]]` на **существующие** заметки вики
(цели ссылок проверены).
- **Правила и статблоки вынесены в справочник**, а не разбросаны посреди сцен; источник
из `books/` указывается при необходимости, сцены лишь отсылают к справочнику.
- **Ремарки Рассказчика** даны курсивом внутри сцен, **реплики НПЦ** — блок-цитатами
(см. «Тон и стиль» выше).
- **Нет открытых `TODO`, заглушек и неснятых плейсхолдеров** `<…>`.

Стоп-условие лупа: принятие сценария пользователем **ИЛИ** N проходов без критических правок.
В `scenario-loop` дополнительно проверяется стилевой профиль Labynight; он дополняет этот
DoD, но не заменяет его как канон готовности.
